# Окно завоза

Прогноз того, когда откроется и закроется сезонный путь Якутии (зимник, ледовая переправа),
и график отправок для опорных складов северного завоза по этому прогнозу.
Только открытые данные, без датчиков. Кейс-чемпионат, кейс А3.

| 🌍 **Переносимость на другие регионы** | [reports/transferability.md](reports/transferability.md) — проверка на 5 регионах вне Якутии |

**Регионы:** Якутия, ЯНАО, Красноярский край, Иркутская и Архангельская обл. (задаются в `okno/regions.py`; в дашборде — переключатель «Регион»). Модель М1 обучается на всех регионах сразу, «до/после» считается по каждому посту (`reports/before_after.md`). Коми не включена: проверка переносимости не прошла.

**Притоки Лены:** ~50 точек по Лене и её притокам (Алдан, Вилюй, Олёкма, Витим) со спутниковыми датами вскрытия 2001–2024 (`scripts/lena_points.py`). Для них — **отдельная модель закрытия** (`models/m1_close_lena.cbm`): на этих точках она точнее календаря на 13–31%, а в общем обучении старым точкам не помогала (`reports/lena_experiment.md`). Прогноз открытия для притоков не строится — там нет замеров толщины льда.

**Журнал прогнозов:** каждый день прогноз по всем путям пишется в `data/forecast_log/forecasts.csv`; фактические даты событий команда вносит в `data/forecast_log/facts.csv` — сверка в `reports/forecast_journal.md`. Живой прогноз выпускается на сегодня: последние дни и прогноз погоды на 16 дней — `data/weather_recent/`. Устойчивость экономики — `reports/stress_test.md`.

**Изменение для А3:** график завоза по вероятностному прогнозу окна вместо календаря.
**Пилот:** переправа Якутск — Нижний Бестях и зимник на Батагай (Верхоянский арктический район).

## Сквозной коридор А3 в ветке kirill

После слияния dmitrii добавлена вкладка «Сквозной коридор (А3)». Она сравнивает
отсутствие предзавоза, предзавоз по календарной медиане, календарному q20 и ML q20.
Сохранены прежние вкладки, приветственный экран, погодный эксперимент и отдельная
сценарная проверка весны 2026 с сезонным допущением 400 000 т.

Каждый день исполняется только новая отправка с хаба. По железной дороге груз
действительно идёт заданное число суток; мощности и место склада ограничены.
Дополнительный склад по умолчанию отсутствует. Заказы в ожидании сохраняются;
штраф начисляется на каждый день их задержки. Все тарифы и мощности — допущения.

В А3 доступны **пять подходов**: четыре прежних правила и экономический план по ML q20.
Новый планировщик выбирает суточную загрузку ж/д
и переправы по минимуму затрат на перевозку, хранение и ожидание, с выполнением спроса
к общему сроку, если это возможно. Он учитывает только информацию, доступную на день
решения. Расходы за период и оценка будущего довоза остатка показаны отдельно для всех
способов. Подбор целых машин не моделируется; преимущество ML не предполагается заранее.
Недельное сравнение показывает прежний и экономический ML: отправку из хаба, прибытие
в Нижний Бестях, переправу и выдачу потребителю. Неделя — семь дней от начала сценария;
есть таблица, график и выгрузка CSV. Дневной журнал сохранён для подробной проверки.
[Алгоритм, результаты и ограничения](reports/economic_planner.md).

**Прежние выводы «−31% на 24 реальных сезонах» и «7/7 PASS» отозваны.**
Полные подтверждённые окна переправы есть для 2019, 2023 и 2024 годов; неизвестные
фазы не восстановлены как факты. В 2024 году первый полностью закрытый день —
16 апреля, паромы открылись 24 мая: разрыв 38 суток. Источники с URL —
[data/rosstat_prices/yakutsk_mchs_crossing_dates.csv](data/rosstat_prices/yakutsk_mchs_crossing_dates.csv).

ML физического вскрытия проверен с расширением только прошлых лет, с фиксированной
датой оценки 10 марта и номинальным лагом ERA5 пять суток. Калибровка также использует
прошлые ошибки. Для дорожных фаз используется отдельное преобразование по предыдущим
подтверждённым годам. Его точность ограничена; при нехватке данных ML явно заменяется
календарным q20. Старый артефакт `window_a3_open.cbm` в новом коридоре не применяется;
прежний прогноз открытия зимников из базовой М1 сохранён.

## Как повторить расчёт

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt     # requirements-data.txt — если пересчитывать спутниковые слои
python run_all.py                 # сборка данных → проверки → М1 → «до/после»
streamlit run app/dashboard.py    # дашборд
```

При запуске открывается приветственный экран «Окно завоза». Кнопка «Открыть дашборд»
ведёт к карте, прогнозам и планировщику; «Скачать описание проекта (PDF)» скачивает
приложенное описание из `app/assets/project.pdf`. Вернуться к вступлению можно кнопкой
«О проекте» в боковой панели. Данные и модели загружаются только при входе в дашборд.

Проверки интерфейса и погодной модели (после установки `requirements.txt`):

```bash
python -m unittest discover -s tests -v
```

**Сценарная проверка весны 2026 (ветка kirill).** В боковой панели нажмите
«Эксперимент: весна 2026»: откроется сравнение пяти способов завоза
Нижний Бестях → Якутск с 16 марта 2026 года. Сезон, путь, дата и параметры
подставляются автоматически; объём, парк и расходы можно менять.
Общий сезонный объём **400 000 т** задан пользователем как допущение и вводится
отдельно от остатка на дату решения. Фактический остаток на 16 марта неизвестен;
прежние 5 000 т сохранены как тестовая партия. Допускаются остатки больше 100 000 т
и парк больше 100 машин; есть условная оценка парка для всего сезонного объёма.
Ограничения движения и наблюдения Sentinel-1 реальные, заказ и экономика —
допущения. Для исходных 5 000 т наш план дороже календаря на 8,56% и завершает
доставку на 13 дней раньше; отдельный выигрыш М1/М2 не подтверждён.
Полный расчёт, снимки, чувствительность и ограничения:
[reports/yakutsk_spring_2026.md](reports/yakutsk_spring_2026.md).
Повторный расчёт по сохранённым входам: `python scripts/replay_yakutsk_2026.py`.

**Погодная модель закрытия (эксперимент, ветка kirill).** В боковой панели есть
отдельный переключатель, выключенный по умолчанию. Он включает М1, обученную с
архивными прогнозами GFS для переправы Якутск — Нижний Бестях. Используются ближайшие
6 суток; это не архив полного прогноза на 14–28 дней. Погодная модель проверена
последовательно на сезонах 2022–2024 с обучением только на более ранних сезонах.
Средний выигрыш к М1 без погоды — около 1,3%; за 7 и 14 дней улучшения нет,
интервалы ненадёжны. Поэтому модель сохраняет пометку экспериментальной;
её можно выключить переключателем в боковой панели. Открытие путей
не меняется; для гидропостов, дат из обучения и при неполном архиве работает обычная М1.
Подробная проверка и ограничения: [reports/weather_close.md](reports/weather_close.md).

```bash
python scripts/download_weather_forecasts.py --start-year 2021 --end-year 2024
python scripts/train_weather_close.py
python scripts/download_weather_forecasts.py --live
```

Последняя команда сохраняет прогнозы на сегодня и вчера, не стирая прошлые выпуски.
Она также добавлена в workflow ежедневного обновления; для ветки `kirill` workflow
можно запускать вручную с выбором этой ветки. Переобучение выполняется отдельно;
обычный `run_all.py` не заменяет экспериментальную модель. Исходные модели М1 и
их отчёты не перезаписываются. Схемы путей на карту не добавляются.

Страница проекта для GitHub Pages собирается в `docs/` (`scripts/build_site.py`, входит в `run_all.py`);
документ проекта — `docs/project.pdf`.

**Автообновление.** Каждый день в 06:00 МСК GitHub Actions
(`.github/workflows/daily-update.yml`) докачивает свежую погоду ERA5, перепроверяет данные,
пересобирает страницу проекта и коммитит результат; дашборд и страница обновляются сами.
Полный пересчёт с обучением М1 — вкладка Actions → «Ежедневное обновление данных» → Run workflow → full.
Перед работой с кодом делайте `git pull`: робот коммитит в main каждый день.

Данные уже лежат в `data/`. Скачать заново: `python scripts/download_data.py`
(погода ERA5 из Open-Meteo ограничена по частоте — скрипт ждёт и продолжает сам).

## Модели

- **М1 — прогноз окна.** Физика: закон Стефана `h = α·√FDD` (α подобран по реальным замерам толщины,
  см. `reports/stefan_calibration.csv`) и сумма оттепельных градусо-дней для весны.
  Поверх — CatBoost с квантильной функцией потерь (10/50/90%), предсказывает отклонение от календаря.
  Сравнение: календарь (средняя дата за прошлые 10 сезонов) и чистая физика.
  Проверка: сезон выкидывается целиком; MAE за 7/14/28 дней до события и покрытие диапазона 10–90%.
- **М3 — планировщик.** 1 000 сценариев даты закрытия из М1, минимизация ожидаемых расходов:
  перевозка + хранение при раннем завозе + дорогой канал для недовезённого.

## Словарь данных

Дни сезона: `0` = 1 сентября, гидрологический год `hydro_year = Y` — сезон с сентября Y−1 по август Y.

| Файл | Строка | Ключевые поля | Единицы | Тип источника |
| --- | --- | --- | --- | --- |
| `data/weather/*.csv`, `data/weather/gauges/*.csv` | точка × сутки | `temperature_2m_mean/min/max`, `snowfall_sum`, `precipitation_sum` | °C, см, мм | реанализ (ERA5) |
| `data/processed/gauges.csv` | гидропост | `gauge_code`, `lat`, `lon`, `region`, `yakutia` | ° | замер |
| `data/processed/hydro_ice_thickness.csv` | пост × дата замера | `ice_cm` (очищено), `ice_cm_raw`, `spike`, `frozen_to_bottom` | см | замер |
| `data/processed/hydro_ice_seasons.csv` | пост × сезон | даты `first_ice`, `freezeup`, `melt_start`, `drift_start`, `ice_end`; `open_{10,20,30}t_*` — лёд достиг нормативной толщины; `valid`, `flags` | дата / день сезона | замер |
| `data/processed/yakutsk_sat_seasons.csv` | сезон | `sat_freezeup_*`, `sat_breakup_*`, `sat_ice_duration_days` | дата / день сезона / сут | спутник |
| `data/processed/m1_dataset_*.csv` | точка × сезон × дата выпуска | признаки М1, `target_day`, `cal_target`, `lead_days` | — | производные |

Нормативная толщина для нагрузки P т — допущение `h = 11·√P` см (10 т → 35 см, 20 т → 49 см),
сверить с ОДН 218.010-98. Экономика М3 (объёмы, тарифы, хранение) — синтетика/допущения,
не участвует в оценке точности М1.
