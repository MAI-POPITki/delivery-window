# Сохранённое ядро ZXC

> Обновлено 08.11.2026: инструмент включён в общую вкладку «Маршрут и план завоза». Актуальная архитектура и границы данных — в [JOURNEY_WORKSPACE.md](JOURNEY_WORKSPACE.md). Описание прежнего самостоятельного интерфейса ниже сохранено как история; отдельного входа с главной страницы больше нет.


Оставлен общий интерфейс календарей доступности в okno/supply_scenarios.py:
период закрытия, окно работы, отдельные дни обслуживания и произвольный календарь.
Это позволяет подключить реальное расписание к существующему оптимизатору,
не создавая ещё одну модель экономики. Отдельного экрана нет.

Импорт таблицы day,available проверяет наличие каждого дня, пропуски и дубли.
compare_supply передаёт календарь в существующий коридор. Прежние вызовы без
availability сохраняют поведение main.

Календарь предполагается известным заранее и применяется и в плане, и при
исполнении. Это сценарный расчёт, не проверка исторического прогноза и не
доказательство экономии. Условия исходного коридора сохраняются: делимые тонны,
нулевой лаг второго участка, оценка будущего довоза остатка после горизонта.
Фактический будущий календарь нельзя выдавать за оперативный прогноз.

На карте спутниковый слой и притоки выключены по умолчанию, но доступны по флажку.

## Проверка

    python -m unittest discover -s tests -p test_supply_scenarios.py -v
    python -m unittest discover -s tests -p test_economic_planner.py -v
    python -m unittest discover -s tests -p test_service_mode.py -v

Тесты проверяют календарь, лаг, склад, баланс и невыполненные заказы.
Независимый полный перебор маленькой задачи подтверждает оптимум для всех восьми
трёхдневных календарей. Одинаковые условия сверяются с исходным коридором.

## Проверка загрузки машины (ZXC)

Во вкладке «Планировщик» доступен раскрывающийся блок проверки полной массы.
Он использует точку и дату левой панели; конкретную дорогу пользователь выбирает
сам, поскольку один гидропост может быть связан с несколькими дорогами.

Источник — существующий data/external/road_events.csv. Используются фактические
события того же сезона, опубликованные не позднее даты решения. Структурированные
limit20 и limit30 дают ограничение полной массы; open без отдельного численного
поля массы не интерпретируется как разрешение. close, конфликтующие записи и
неизвестная дата публикации блокируют положительный вывод.

Масса = пустая машина с оборудованием + груз. Выводятся превышение в тоннах и
процентах от ограничения и остаток под груз. Процент превышения не является
вероятностью аварии. Реестр неполон: результат не подтверждает действующий режим
движения, не проверяет осевые нагрузки или техническую грузоподъёмность машины.
М1 и формула толщины льда не подменяют ограничения дорожного ведомства.
Недельный план М3 от этой проверки не меняется.

Проверка: python -m unittest discover -s tests -p test_truck_load.py -v
