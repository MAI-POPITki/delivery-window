# Сохранённое ядро ZXC

Оставлен общий интерфейс календарей доступности в okno/supply_scenarios.py:
период закрытия, окно работы, отдельные дни обслуживания и произвольный календарь.
Это позволяет подключить реальное расписание к существующему оптимизатору,
не создавая ещё одну модель экономики. Отдельного экрана нет.

Импорт таблицы day,available проверяет наличие каждого дня, пропуски и дубли.
compare_supply передаёт календарь в существующий коридор. Прежние вызовы без
availability сохраняют поведение main.

Календарь предполагается известным заранее и применяется и в плане, и при
исполнении. Это сценарный расчёт, не проверка исторического прогноза и не
доказательство экономии. Условия исходного коридора сохраняются: делимые тонны,
нулевой лаг второго участка, оценка будущего довоза остатка после горизонта.
Фактический будущий календарь нельзя выдавать за оперативный прогноз.

На карте спутниковый слой и притоки выключены по умолчанию, но доступны по флажку.

## Проверка

    python -m unittest discover -s tests -p test_supply_scenarios.py -v
    python -m unittest discover -s tests -p test_economic_planner.py -v
    python -m unittest discover -s tests -p test_service_mode.py -v

Тесты проверяют календарь, лаг, склад, баланс и невыполненные заказы.
Независимый полный перебор маленькой задачи подтверждает оптимум для всех восьми
трёхдневных календарей. Одинаковые условия сверяются с исходным коридором.

## Что удалено

Дублирующая вкладка, повторные региональные модельные отчёты, слабо связанные
с расчётом примеры источников и перевод вскрытия в навигационную дату через
произвольный сдвиг. Изменения команды из main сохранены.
Предыдущая реализация доступна в истории Git, без копий в рабочем коде.
