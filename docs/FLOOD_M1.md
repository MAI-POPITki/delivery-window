# Как работает М1 паводков

М1 отвечает на вопрос: **какой уровень воды будет на данном гидропосту через
1–7 суток, если на выбранную дату известны ежедневные измерения?** Уровень —
в сантиметрах над нулём поста. Это собственная обученная модель, не пересказ
GloFAS. GloFAS остаётся отдельным внешним источником расхода в м³/с.

## Какие данные используются

Сохранены исходные ответы публичного сервиса [Уровень-Спутник](https://level-satellite.ru),
авторы П. П. Головлев и А. И. Иннокентьев. Для Якутска (3045) и Ишима (11412)
выбран только источник `gmvo`, опубликованный сервисом как АИС ГМВО, 2008–2023.
Для Оренбурга (19063) и Орска (19054) — только `vodinfo`, архив до 09.09.2025.
Разные источники внутри одного ряда не смешиваются. Это вторичная публикация:
полной независимой сверки всех измерений и истории нулей постов пока нет.

Исходные JSON.gz лежат в `data/flood/levels/`, рядом — код и координаты поста,
параметры запроса, время получения, источники и SHA-256. При загрузке проверяются
хеш, код поста, уникальность дат и конечность чисел. Отрицательный уровень допустим:
это положение относительно условного нуля. Пропуски не интерполируются.
Курган исключён: однородного архива для обучения недостаточно.

Текущих измерений за 2026 год в сохранённом архиве нет. Поэтому интерфейс
даёт исторический расчёт, а не сегодняшний оперативный прогноз. Архив получен
позднее; точный состав данных, доступный оператору в прошлый день, не восстановлен.

## От измерения к прогнозу

1. Пользователь выбирает гидропост, дату решения и горизонт. За выбранный день
   должно быть измерение. Для признаков нужны значения с лагами до 30 суток;
   последние 30 ежедневных значений нужны также для среднего.
2. Из ряда физически отрезаются все даты после решения. Модель получает текущий
   уровень; лаги 1/3/7/14/30 дней; изменения за 1/3/7/14 дней; средние за 7/30 дней;
   синус и косинус дня года; горизонт. Всего 15 признаков.
3. CatBoost обучается предсказывать **изменение уровня**, а не абсолютную отметку.
   Для каждой станции своя модель, общая для семи горизонтов. v2 использует
   MultiQuantile 0.1/0.5/0.9, 200 деревьев, глубину 5, learning rate 0.06, L2 10,
   seed 42. Прибавление текущего уровня даёт квантили будущей отметки.
4. Медиана CatBoost сравнивается с тремя правилами: оставить текущий уровень,
   взять медиану прошлых лет для целевой календарной даты, повторить прошлогодний
   уровень на целевую дату. Метод выбирается по MAE предыдущего года отдельно
   для каждого горизонта. Если выбран простой метод, интерфейс это прямо сообщает.
5. Для CatBoost диапазон q10–q90 расширяется CQR-поправкой по ошибкам предыдущего
   года. Ошибка калибровки: `max(q10 − факт, факт − q90)`. Поправка — неотрицательная
   порядковая статистика ранга `ceil((n+1) × 0.8)`. Для простого правила используется
   квантиль его абсолютных ошибок и симметричный диапазон вокруг прогноза.
   Отдельная калибровка для апреля–июля и остальных месяцев по дате решения;
   если в сезоне менее 60 примеров — берётся весь предыдущий год.

В интерфейсе раздел «Как получен этот прогноз» показывает исходный уровень,
изменения, выбранный алгоритм, год калибровки и фактическую поправку в сантиметрах.
Сортировка квантилей устраняет их пересечения. Диапазон ориентирован на 80%
покрытия, но зависимости в суточном ряду и изменение режима реки исключают
заявление гарантии покрытия. Это не вероятность затопления территории.

## Как предотвращается использование будущего

Для прогноза года Y модель обучается только на целевых датах по Y−2 включительно.
Y−1 служит выбору метода и калибровке. Y используется только для проверки.
Нужно минимум восемь прошлых лет с ≥90% ежедневных наблюдений. Версии привязаны
к SHA-256 исходного архива, станции и источнику. Изменение архива требует переобучения.
Тест меняет будущие уровни на +100000 см: прогноз выбранной даты обязан остаться тем же.

Для v2 период 2019–2024 уже изучался при создании v1 и потому обозначен как
**повторная оценка**. Дополнительно показан 2025 год Оренбурга/Орска до 09.09.
Параметры v2 зафиксированы в протоколе до обучения; после просмотра результатов
не подбирались. Все отрицательные результаты сохраняются.

## Результаты и практический предел

В апреле–июле на горизонте семь суток, на одинаковых датах с v1:

| Пост | MAE v1 → v2, см | Покрытие v1 → v2 | Средняя ширина v1 → v2, см |
| --- | ---: | ---: | ---: |
| Якутск | 57.1 → 64.6 | 68% → 84% | 132 → 204 |
| Ишим | 26.9 → 28.1 | 48% → 81% | 27 → 77 |
| Оренбург | 29.7 → 25.1 | 56% → 75% | 19 → 46 |
| Орск | 22.0 → 18.9 | 61% → 82% | 21 → 51 |

Более надёжный диапазон потребовал большей ширины; точечная ошибка Якутска
и Ишима на семь суток немного выросла. Interval score, штрафующий и ширину,
и промахи, улучшился у всех четырёх постов. На одни сутки среднегодовая MAE v2:
Якутск 6.0 см против 10.9 см у сохранения уровня; Ишим 1.2 против 4.4 см.

**Экстремальный паводок остаётся слабым местом.** Весной 2024 года на семь суток
Оренбург: MAE 64.2 см, покрытие 58%; Орск: MAE 54.5 см, покрытие 67%.
Средняя оценка по годам скрывает этот провал, поэтому интерфейс показывает
также худший год. Весной 2025 года MAE на семь суток: Оренбург 14.0 против
20.1 см у сохранения уровня, Орск 12.3 против 15.0 см. Покрытие 98% и 95%,
но ширина около 105–106 см: после экстремального калибровочного 2024 года
диапазоны широкие. Один дополнительный год не подтверждает устойчивость модели.

Полные таблицы всех горизонтов, сезонов, годов, ширины и interval score:
[отчёт](../reports/flood_m1_quantile.md),
[CSV метрик](../reports/flood_m1_quantile_scores.csv).
v1 сохранена и доступна в переключателе для сравнения.

## Насколько это аналог М1 зимников

| Свойство | М1 зимников | М1 паводков v2 |
| --- | --- | --- |
| Цель | Дата открытия/закрытия пути | Уровень на 1–7 суток |
| Основа | CatBoost 10/50/90%, поправка к календарю | CatBoost 10/50/90%, изменение текущего уровня |
| Входы | Погода, лёд, сезон, физическая оценка | Только история измеренного уровня и сезон |
| Модели | Общая по точкам | Отдельная для каждого поста |
| Диапазон | Квантильный + конформная поправка | Квантильный + сезонная CQR по прошлому году |
| Проверка | Исключение целого сезона | Строго прошлые годы → следующий год |
| Прикладной результат | Оценка даты сезонного события | Уровень; связь с затоплением и дорогой пока не проверена |

По устройству вероятностного прогноза v2 стала ближе к зимникам. Равенство
практического качества не доказано: разные цели, единицы ошибок и объём проверки.
Нет погоды, снегозапасов, подпора, работы водохранилищ и верхних постов; экстремальный
новый режим может не следовать прошлой динамике. Следующий содержательный шаг —
получить текущие уровни и архивы дополнительных физических факторов с известной
датой доступности, затем провести новую проверку без настройки на её результатах.

## Воспроизведение

Из корня репозитория, с установленными `requirements.txt`:

```powershell
python scripts/download_flood_levels.py
python scripts/train_flood_m1.py
python scripts/train_flood_m1_quantile.py
python -m unittest discover -s tests -p 'test_flood*.py'
```

Первый шаг обращается к живому источнику и может изменить архив: для точного
повторения опубликованных метрик используйте уже сохранённые JSON.gz и манифесты.
Пересобрать только отчёт из сохранённых прогнозов:
`python scripts/train_flood_m1_quantile.py --report-only`.
