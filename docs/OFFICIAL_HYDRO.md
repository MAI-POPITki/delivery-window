# Официальные наблюдения Росгидромета

В карточках точек и во вкладке «О данных» появился отдельный слой официальных
измерений и сводок. Он охватывает все точки семи регионов из `okno.regions`:
Якутия, ЯНАО, Красноярский край, Иркутская и Архангельская области,
Магаданская область и Чукотка. Если в источниках нет измерений конкретного
поста, интерфейс показывает отсутствие замеров и доступные региональные сводки.
Наличие региона в сервисе не означает наличие новых замеров каждого его поста.

## Источники и фактический смысл записей

- [ГИС «Метео ДВ»](https://meteo-dv.ru/hydro_dfo/) — фактические уровни воды
  и публичные карточки постов. [Руководство пользователя](https://meteo-dv.ru/hydro_dfo_test/assets/docs/instruction.pdf),
  стр. 4: гостевой просмотр распространяется на весь ДФО. Загрузчик повторяет
  обычные запросы гостевого интерфейса без авторизации; это не гарантированный
  поставщиком API. Изменение формата или недоступность сервиса сохраняет старый снимок.
- [Якутское УГМС, «Реки Якутии»](https://ykuthydromet.ru/reki/) — датированный
  календарь сводок за 2022–2026 годы.
- [Росгидромет, RSS](https://www.meteorf.gov.ru/press/news/rss/) и
  [сводки 2026 года](https://www.meteorf.gov.ru/press/polovod2026/) — новые выпуски
  автоматически обнаруживаются по гидрологическим заголовкам.
- [Сибирский центр НИЦ «Планета»](https://www.rcpod.ru/news/) — официальные
  спутниковые обзоры ЯНАО, Красноярского края и Иркутской области с материалами УГМС.
- [Северное УГМС](https://www.sevmeteo.ru/weather/gidro/) — месячные обзоры
  Архангельской области. Применяются условия источника: ссылка обязательна,
  использование некоммерческое, исследовательское. Атрибуция есть в интерфейсе.

## Проверки смысла и времени

Пост сопоставляется по исходному индексу **и** реке с названием пункта.
Ближайшие координаты сами по себе не служат основанием для сопоставления.
Для переправы используется явно обозначенный опорный пост «Лена — Якутск»,
а не утверждение о замере на самой ледовой дороге. Спутниковые точки не
получают выдуманных гидропостов. Расхождения координат сохраняются в примечаниях.

Уровни хранятся в сантиметрах над нулём поста. Отрицательные уровни и нулевые
значения допустимы; служебный пропуск `999.999` исключается. Дата запроса
не заменяет дату измерения. Данные `prev_y` из графика источника исключены:
сайт рисует прошлогодние уровни на координатах времени текущего года.
Показания другого прибора `agk` не смешиваются с рядом поста.

В карточке «Метео ДВ» поле `ice_level_last` не сопровождается датой замера.
Оно сохраняется как `undated`, показывается с предупреждением об отсутствии
даты и не используется как текущая толщина льда. Диапазоны из текста, например
90–124 см на участке Покровск — Якутск — Кангалассы, остаются сводками по участку.
Середина диапазона не становится точным замером у Якутска. Морские ледовые
обзоры исключены. Ледостав или вскрытие не превращаются в даты допуска транспорта.

У каждого измерения сохранены дата наблюдения, время первого получения
проектом, первоисточник и SHA-256 исходного ответа. Исправленная поставщиком
величина получает собственное время доступности. История не приобретает
знание будущих измерений задним числом. Измерения из графика и списка постов
с одним временем и значением объединяются независимо от формата даты.

## Влияние на модели

Новые сведения видны в карточках, таблице покрытия и CSV-выгрузках. Свежий
датированный снег **на льду у этого же поста**, уже доступный на дату решения,
может попасть в существующую экспериментальную снежную модель. Снег на суше,
диапазоны по рекам и значения без даты не заменяют этот признак.

Архивы Arctic Data Center и PANGAEA, обучающие цели, веса моделей и результаты
прошлых проверок не переписаны. Новая публикация не является основанием
автоматически переобучать М1 на сводках или заявлять улучшение точности.
Временная метка снимка входит в ключ кэша прогнозов и обновляет интерфейс.

## Автоматическое обновление

`okno.hydro_refresh` запускает один фоновый поток на процесс приложения.
Раз в час проверяется срок последнего опроса; обновление выполняется раз в
6 часов при работающем сервере. Сеть не блокирует первый показ дашборда.
Проверка файла раз в минуту подхватывает новый снимок в открытом интерфейсе.
Блокировка файла исключает одновременную запись несколькими процессами,
а атомарная замена JSON исключает чтение наполовину записанных данных.

При недоступности отдельного источника его предыдущие записи остаются.
Просроченное измерение не обозначается свежим. Исходные ответы сохранены
сжатыми в `data/official_hydro/raw/`, реестр — в `snapshot.json`.

В существующий daily workflow добавлены загрузка и проверка целостности.
GitHub запускает cron только из ветки по умолчанию: изменение workflow в
`kirill` само по себе не включает отдельный cron этой ветки. Поэтому фоновое
обновление работающего Streamlit не зависит от изменений `main`.
При остановке или усыплении сервера загрузки возобновляются после запуска;
самостоятельная выгрузка на GitHub фоновым потоком не выполняется. Постоянный
архив в Git обновляет workflow при запуске на `kirill`.

```bash
python scripts/download_official_hydro.py --bootstrap --history-pages 8
python scripts/download_official_hydro.py
OKNO_HYDRO_AUTO_REFRESH=0 python -m unittest discover -s tests -v
```

Первый запуск дополнительно запрашивает доступные архивные сроки 2025–2026
годов. Параметр `--history-pages` расширяет просмотр официальных архивов.
`OKNO_HYDRO_AUTO_REFRESH=0` выключает только фоновую сеть для автономных тестов.
