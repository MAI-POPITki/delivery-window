# Источники данных высокой воды

Поставщик: https://flood-api.open-meteo.com/v1/flood
Документация: https://open-meteo.com/en/docs/flood-api
Производитель гидрологических расчётов: Copernicus CEMS / GloFAS.
Данные через Open-Meteo, CC BY 4.0; это модельные расходы в м³/с, не замеры.

- `history/`: запрос 1991–2020; 1991–1996 отсутствуют в ответах, не заполняются.
- `latest/`: последние полученные восемь UTC-дней (сегодня + семь полных суток).
- `runs/YYYY-MM-DD/`: первый сохранённый ответ по UTC-дню загрузки, без перезаписи.
  Дата каталога — дата получения, а не неизвестное время инициализации модели.
- `cases/2024/`: исторический модельный ряд для диагностики; это не архив
  оперативных выпусков и не фактические измерения наводнения.
- `routes/`: реальные XML-ответы официального API OpenStreetMap (`*.osm.gz`)
  и метаданные запросов (`*.json`): URL рамки, время UTC, SHA-256 распакованного XML.
  Лицензия — ODbL 1.0, © OpenStreetMap contributors. Это геометрия, не сведения о допуске.

В JSON-конверте: `payload` — ответ поставщика, `url` — полный запрос,
`fetched_at` — UTC-время получения, `model`, `source`, `sha256`.
Контрольная сумма относится к канонизированному JSON `payload`
(`ensure_ascii=True`, `separators=(',', ':')`), не к байтам HTTP-ответа.
Первый выпуск в `runs/` получен с моделью API по умолчанию (v4 по документации);
последующие загрузки явно фиксируют `models=seamless_v4`.

Координаты точек и код расчёта: `okno/flood.py`. Координаты — речные ячейки модели,
не официальные гидропосты. Центр города может оказаться на другой малой реке.
Источник даёт разрешение около 5 км; привязка требует дальнейшей независимой проверки.

Обновить: `python scripts/download_flood.py`.
Повторно получить архив и пример: `python scripts/download_flood.py --history --case-year 2024`.
Проверить: `python scripts/validate_flood.py`.
Обновить дорожные геометрии: `python scripts/download_flood_routes.py`.
Полный протокол: `docs/FLOOD_VALIDATION_PLAN.md` и `reports/flood_implementation_checks.md`.
